# Развернуть стенд на сервере

Стенд живёт постоянно: он держит часы, будит сессию по расписанию, доводит заявку до
стакана и пишет всё, что произошло. Поэтому ему нужна обычная машина с докером, а не
среда, где процесс поднимается по запросу и умирает после ответа.

## Что понадобится

- **Машина** с Docker и Docker Compose, архитектура **x86_64**: опубликованные образы
  собраны под неё. Два ядра и 4 ГБ памяти достаточно - стек в покое занимает около
  240 МиБ и растёт, пока сессия думает.
- **Домен**, указывающий на адрес машины. Запись в DNS должна разойтись **до** первого
  запуска: сертификат берётся по вызову на 80-й порт, и без работающего имени его
  просто не выдадут.
- **Ключи брокера** и вход в агента - о них ниже.

Ближе к бирже - лучше. Отбор проходит сотни бумаг за проход и ограничен числом запросов
в минуту, а защита решает по цене каждые пятнадцать минут: сотня лишних миллисекунд на
запрос растягивает проход настолько, что список успевает устареть раньше, чем обновится.

## Поставить

```
git clone https://github.com/swiftward/swiftward-alpaca-options-agents.git
cd swiftward-alpaca-options-agents
cp .env.example .env
```

Дальше `.env` заполняется по месту. Обязательное:

| Что | Зачем |
|---|---|
| `ALPACA_API_KEY_ID`, `ALPACA_API_SECRET_KEY` | счёт, которым торгуем |
| `DASHBOARD_HOST`, `ACME_EMAIL` | домен страницы и почта для сертификата |
| `TELEGRAM_*` | комната, в которой сессия говорит и слышит |
| `AGENT_MODEL` | какой моделью думает сессия |
| `IMAGE_TAG` | какие образы забирать, см. ниже |
| `SCREENER_UNDERLYINGS` и прочие `SCREENER_*` | что отбор просматривает; **пустой список выключает и его, и инструмент кандидатов у сессии - молча** |

Остальное имеет разумные значения в `.env.example` и правится по надобности.

## Войти в агента

Агент не стартует без входа: он не угадывает, кем он работает. Вход делается на самой
машине.

```
ssh -L 1455:localhost:1455 you@server
codex login
```

Проброс порта нужен потому, что вход возвращается в браузер, а на сервере браузера нет:
команда напечатает адрес, откроешь его у себя. Если браузер не годится вовсе, тот же
`codex login` принимает ключ или токен со стандартного ввода. Проверить: `codex login
status`.

Вход обновляет себя по ходу работы, поэтому каталог с ним живёт в томе и переживает
перезапуск.

## Поднять

```
make prod-up
```

Стек забирает опубликованные образы по `IMAGE_TAG` и поднимается. Наружу смотрит один
контейнер - прокси; он же берёт сертификат. Остальные доступны только внутри.

**Пришпиливай образы к коммиту, а не к `latest`.** Каждая сборка публикуется дважды: под
`latest` и под меткой коммита. Стенд, стоящий на метке коммита, отвечает на вопрос «что
именно сейчас работает», а откат сводится к смене одной строки.

## Убедиться, что поднялось

Мало увидеть, что контейнер запущен: процесс может стоять на старте и выглядеть живым.
Ищи в журнале агента **две** строки:

```
conversation ready
started
```

Первая говорит, что разговор с агентом открыт, вторая - что расписание работает. Строка
о том, что служба слушает порт, ничего из этого не означает.

Дальше - живой признак: в базе появляются снимки счёта, а в назначенное время в записи
появляется ход.

## Обновлять

```
git pull
docker compose --env-file .env -f compose.prod.yaml pull
make prod-up
```

**Не во время торгов.** Перезапуск обрывает идущий ход, а ход - это принятое решение:
сессия может успеть записать намерение и не успеть отправить заявку. Обновление стенда -
решение человека и делается в закрытый рынок.

## Если агент отказался стартовать про каталог приёмов

Он говорит это внятно и называет причину. Каталог приёмов в рабочем томе принадлежит
процессу, который его разложил, и удалить чужое он не станет. Такое бывает после
обновления с версии, где приёмы клал entrypoint. Команда - в `agent/README.md`, там же
объяснено, почему она разовая.
