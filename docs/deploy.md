# Развернуть стенд на сервере

Стенд живёт постоянно: он держит часы, будит сессию по расписанию, доводит заявку до
стакана и пишет всё, что произошло. Поэтому ему нужна обычная машина с докером, а не
среда, где процесс поднимается по запросу и умирает после ответа.

## Что понадобится

- **Машина** с Docker и Docker Compose, архитектура **x86_64**: опубликованные образы
  собраны под неё. Два ядра и 4 ГБ памяти достаточно - стек в покое занимает около
  240 МиБ и растёт, пока сессия думает.
- **Домен**, указывающий на адрес машины. Запись в DNS должна разойтись **до** первого
  запуска: сертификат берётся по вызову на 80-й порт, и без работающего имени его
  просто не выдадут.
- **Ключи брокера** и вход в агента - о них ниже.

Ближе к бирже - лучше. Отбор проходит сотни бумаг за проход и ограничен числом запросов
в минуту, а защита решает по цене каждые пятнадцать минут: сотня лишних миллисекунд на
запрос растягивает проход настолько, что список успевает устареть раньше, чем обновится.

## Поставить

```
git clone https://github.com/swiftward/swiftward-alpaca-options-agents.git
cd swiftward-alpaca-options-agents
cp .env.example .env
```

Дальше `.env` заполняется по месту. Обязательное:

| Что | Зачем |
|---|---|
| `ALPACA_API_KEY_ID`, `ALPACA_API_SECRET_KEY` | счёт, которым торгуем |
| `DASHBOARD_HOST`, `ACME_EMAIL` | домен страницы и почта для сертификата |
| `TELEGRAM_*` | комната, в которой сессия говорит и слышит |
| `AGENT_MODEL` | какой моделью думает сессия |
| `IMAGE_TAG` | какие образы забирать, см. ниже |
| `SCREENER_UNDERLYINGS` и прочие `SCREENER_*` | что отбор просматривает; **пустой список выключает и его, и инструмент кандидатов у сессии - молча** |

Остальное имеет разумные значения в `.env.example` и правится по надобности.

## Войти в агента

Агент не стартует без входа: он не угадывает, кем он работает. Вход делается на самой
машине.

```
ssh -L 1455:localhost:1455 you@server
codex login
```

Проброс порта нужен потому, что вход возвращается в браузер, а на сервере браузера нет:
команда напечатает адрес, откроешь его у себя. Если браузер не годится вовсе, тот же
`codex login` принимает ключ или токен со стандартного ввода. Проверить: `codex login
status`.

Вход обновляет себя по ходу работы, поэтому каталог с ним живёт в томе и переживает
перезапуск.

## Войти в реестр образов

Образы лежат закрытыми пакетами, и это выбор, а не недоделка. Публичные пакеты
избавили бы сервер от секрета, но в образ агента упакован каталог `agent/` -
декларация, приёмы, `AGENTS.md`, то есть вся торговая логика открытым текстом.
Репозиторий открывается в день сдачи; отдавать логику на неделю раньше тем, кто
ещё торгует, незачем. (Заодно организация публичные пакеты и не разрешает: это
её политика, снять может только владелец.)

Значит серверу нужен токен ТОЛЬКО НА ЧТЕНИЕ. Классический, с единственной
областью `read:packages`:

```
https://github.com/settings/tokens/new?scopes=read:packages&description=alpaca-stand-ghcr
```

Кладётся один раз, не показываясь ни в истории команд, ни в переписке:

```
read -rs "T?токен: "
printf '%s' "$T" | ssh -i ~/.ssh/alpaca-swiftward root@<адрес> \
  "docker login ghcr.io -u <твой-логин> --password-stdin"
unset T
```

Две мелочи в этой строке не случайны. Подсказка задана как `"T?токен: "`, а не
через `-p`: в zsh `-p` означает «читать из сопроцесса» и даёт `no coprocess`. И
токен идёт через стандартный ВВОД, а не в аргументах команды - иначе он виден в
списке процессов на обеих машинах, пока команда выполняется.

Дальше `pull` работает как с публичными. Секрет живёт в `~/.docker/config.json`
на сервере и больше нигде - в `.env` его класть НЕ надо, иначе он поедет в
резервные копии и в чужие глаза.

## Что в .env обязано быть непустым

Копия `.env.example` не годится: часть значений там пуста намеренно, и служба с
пустым значением не работает вполсилы, а **не стартует вовсе**. Проверено
подъёмом 28 августа - оба отказа нашлись именно так.

| переменная | без неё | отказ |
|---|---|---|
| `ENVELOPE_CALLERS` | конверт | `the envelope role would recognise nobody` |
| `THREAD_RESUME_LIMIT` | харнесс | помнить тред можно только с пределом на возобновление |
| `GATEWAY_TOKEN` | конверт и агент | сессия не докажет, кто она |
| `ENVELOPE_IDENTITY` | лестница | принуждать будет нечем: она читает предел этого имени |
| `RECORD_DATABASES` | миграции | накатывать некуда |
| `ALPACA_API_KEY_ID` и секрет | сервер брокера | перезапускается по кругу |
| `BROKER_MCP_URL` | агент | брокера нет вовсе |
| `PAGE_MCP_TOKEN` | страница | деньги не показывает, отвечает 503 |
| `SCREENER_KEEP` | харнесс | `the screener needs how long to keep what it finds` |
| `CODEX_AUTH_DIR` и вход | агент | `no login at /mnt/codex/auth.json` |

Вход в codex делается один раз и на машине без браузера - только так:

```
docker run --rm -it --entrypoint codex \
  -v /opt/alpaca-stand/codex-auth:/home/agent/.codex \
  ghcr.io/swiftward/swiftward-alpaca-options-agents/agent:<версия> login --device-auth
```

Три подробности, каждая стоила попытки. `--device-auth`, потому что обычный вход
ждёт обратного вызова на `localhost`, и через проброс порта он не проходит.
Каталог принадлежит `1000:1000` - образ работает от этого пользователя, и от root
получается `Permission denied`. И лежит он рядом со стендом, а не под `/root`:
туда контейнеру ходу нет вовсе.

`GATEWAY_TOKEN` и `ENVELOPE_CALLERS` - НАШИ собственные строки, не от брокера и
не от чужого шлюза. Ключ один на агента нарочно: пределы применяются к тому, кто
спросил, и два агента с общим ключом были бы для правил одним агентом.

```
T=$(head -c 24 /dev/urandom | base64 | tr -dc 'A-Za-z0-9' | head -c 32)
printf 'GATEWAY_TOKEN=%s\nENVELOPE_CALLERS=%s=options-alpha\n' "$T" "$T" >> .env
```

Осторожно с записью в `.env` через ssh: `\$T` внутри heredoc уезжает в файл
БУКВАЛЬНО, и compose потом ищет переменную `T`, которой нет. Наступали 28 августа.

## Поднять

```
mkdir -p /opt/alpaca-stand/transcripts
make prod-up
```

Каталог создаётся заранее нарочно. Не создашь - его сделает докер, от root, и агент,
работающий не от root, писать туда не сможет. След работы при этом не появится, а
никакой ошибки не будет: агент просто молча ничего не запишет.

Стек забирает опубликованные образы по `IMAGE_TAG` и поднимается. Наружу смотрит один
контейнер - прокси; он же берёт сертификат. Остальные доступны только внутри.

**Пришпиливай образы к коммиту, а не к `latest`.** Каждая сборка публикуется дважды: под
`latest` и под меткой коммита. Стенд, стоящий на метке коммита, отвечает на вопрос «что
именно сейчас работает», а откат сводится к смене одной строки.

## Где смотреть, что агент делал

Две записи, и они дополняют друг друга, а не дублируют.

`transcripts/` на машине - полный след каждого треда, как его пишет codex: что подано
сессии на вход, какие инструменты вызваны и с каким ответом, что агент сказал в ответ,
и его рассуждения. Формат - JSONL по строке на событие, разложено по датам.

Postgres - то же самое разобранным по таблицам: `turns` (когда, чем разбужена, чем
кончилась), `tool_calls` (инструмент, аргументы, ответ), `intents` (что решено и
почему), `candidates` (что скринер нашёл в последний проход), `account_snapshots` и
`volatility_samples`. Текстов задачи и ответа здесь НЕТ - за ними в `transcripts/`.

## Убедиться, что поднялось

Мало увидеть, что контейнер запущен: процесс может стоять на старте и выглядеть живым.
Ищи в журнале агента **две** строки:

```
conversation ready
started
```

Первая говорит, что разговор с агентом открыт, вторая - что расписание работает. Строка
о том, что служба слушает порт, ничего из этого не означает.

Дальше - живой признак: в базе появляются снимки счёта, а в назначенное время в записи
появляется ход.

## Обновлять

```
git pull
docker compose --env-file .env -f compose.prod.yaml pull
make prod-up
```

**Не во время торгов.** Перезапуск обрывает идущий ход, а ход - это принятое решение:
сессия может успеть записать намерение и не успеть отправить заявку. Обновление стенда -
решение человека и делается в закрытый рынок.

## Если агент отказался стартовать про каталог приёмов

Он говорит это внятно и называет причину. Каталог приёмов в рабочем томе принадлежит
процессу, который его разложил, и удалить чужое он не станет. Такое бывает после
обновления с версии, где приёмы клал entrypoint. Команда - в `agent/README.md`, там же
объяснено, почему она разовая.
